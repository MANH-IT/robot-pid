# ESP8266 – cầu nối WiFi ↔ UART

ESP-01S chạy như một cầu nối byte trong suốt: nhận dữ liệu TCP từ laptop và chuyển nguyên văn xuống UART2 của STM32, theo chiều ngược lại cho telemetry.

Firmware STM32 không cần biết WiFi. Toàn bộ giao thức dòng lệnh giữ nguyên như [uart_protocol.md](uart_protocol.md).

## 1. Sơ đồ đấu dây

| ESP-01S | Nối tới |
|---|---|
| VCC | 3.3 V từ buck riêng (đỉnh > 500 mA) |
| GND | GND chung |
| TX | PA3 (USART2_RX của STM32) |
| RX | PA2 (USART2_TX của STM32) |
| CH_PD / EN | 3.3 V |
| GPIO0 | 3.3 V khi chạy bình thường |
| GPIO2 | để trống hoặc 3.3 V |

Lưu ý:

- Không cấp 5 V vào VCC hoặc chân tín hiệu ESP-01S.
- Không lấy nguồn ESP từ chân 3V3 của Blue Pill.
- Khi nạp firmware, kéo GPIO0 xuống GND rồi reset để vào chế độ nạp.

## 2. Nạp firmware cầu nối

### 2.1 Dùng sketch có sẵn trong repo

File: `firmware/esp8266/esp8266_bridge.ino`.

1. Cài Arduino IDE và board package **esp8266**.
2. Chọn board **Generic ESP8266 Module** (hoặc **ESP-01S** nếu có).
3. Chọn Flash size **1 MB**, upload speed 115200.
4. Nạp sketch qua USB-TTL 3.3 V.
5. Sau khi nạp, ESP phát WiFi:
   - SSID: `Robot-PID`
   - Mật khẩu: `robotpid123`
   - Địa chỉ IP: `192.168.4.1`
   - TCP server: cổng `8080`

### 2.2 Dùng esp-link

Có thể dùng firmware [esp-link](https://github.com/jeelabs/esp-link) thay cho sketch trên. Cấu hình:

- UART: 115200, 8N1.
- TCP server port: 8080.
- WiFi: AP hoặc STA tùy nhu cầu.

Khi dùng STA, đổi địa chỉ trong lệnh host cho đúng IP do router cấp.

## 3. Kết nối từ host

Laptop kết nối WiFi do ESP phát, sau đó chạy:

```bash
cd host
source .venv/bin/activate
python3 main.py --tcp 192.168.4.1:8080
```

Nếu ESP nối vào router nội bộ, dùng IP thực của ESP:

```bash
python3 main.py --tcp 192.168.1.50:8080
```

Chạy không cần GUI:

```bash
python3 main.py --tcp 192.168.4.1:8080 --monitor
```

## 4. Kiểm tra nhanh

Dùng `nc` hoặc `telnet` để xem telemetry:

```bash
nc 192.168.4.1 8080
```

Nếu thấy các dòng `T,...` khoảng 50 lần/giây là cầu nối hoạt động. Gõ `PING` phải nhận `PONG`.

Có thể dùng chế độ monitor của host để kiểm tra:

```bash
python3 main.py --tcp 192.168.4.1:8080 --monitor
```

## 5. Xử lý sự cố

| Hiện tượng | Kiểm tra |
|---|---|
| Không thấy WiFi `Robot-PID` | Nguồn 3.3 V đủ dòng, CH_PD nối 3.3 V, GPIO0 đang ở mức cao khi chạy |
| Kết nối TCP được nhưng không có telemetry | TX/RX có bị đảo? Đúng baud 115200? STM32 đã cấp nguồn? |
| Telemetry bị ngắt quãng | WiFi yếu, giảm khoảng cách, tránh nguồn ESP sụt áp |
| Robot tự dừng sau 500 ms | Host không gửi lệnh 20 Hz hoặc TCP bị mất gói kéo dài |
| Nạp firmware thất bại | Kéo GPIO0 xuống GND, reset ESP, chọn đúng flash size 1 MB |

## 6. Giới hạn

- WiFi thêm trễ và jitter so với USB-UART; nên dùng USB-UART khi hiệu chuẩn PID.
- Timeout 500 ms trong firmware vẫn là lớp bảo vệ cuối cùng khi mất WiFi.
- ESP-01S chỉ có một kết nối TCP tại một thời điểm với sketch mẫu.
