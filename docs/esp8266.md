# ESP8266 – cầu nối WiFi ↔ UART

ESP8266 chạy như một cầu nối byte trong suốt: nhận dữ liệu TCP từ laptop và chuyển nguyên văn xuống USART2 của STM32, theo chiều ngược lại cho telemetry.

Firmware STM32 không cần biết WiFi. Toàn bộ giao thức dòng lệnh giữ nguyên như [uart_protocol.md](uart_protocol.md).

Firmware bridge hiện tại: `esp8266/src/main.cpp`, build bằng PlatformIO với `env:nodemcuv2` (NodeMCU V3). Không dùng sketch Arduino `.ino` cũ.

## 1. Cấu hình mặc định trong firmware

| Thông số | Giá trị | Vị trí |
|---|---|---|
| Board | NodeMCU V3 (`nodemcuv2`) | `esp8266/platformio.ini` |
| WiFi mode | STA (kết nối hotspot) | `WiFi.mode(WIFI_STA)` |
| SSID / mật khẩu | trong `esp8266/src/secrets.h` | `WIFI_SSID`, `WIFI_PASSWORD` |
| TCP server | `8080` | `TCP_PORT` |
| UART STM32 | UART0 sau `Serial.swap()`, 115200 8N1 | `Serial` |
| ESP RX | GPIO13 | `STM32_RX_PIN` |
| ESP TX | GPIO15 | `STM32_TX_PIN` |
| UART debug | qua TCP (log đệm tới khi client kết nối) | `logf()` |

Sao chép `esp8266/src/secrets.example.h` thành `esp8266/src/secrets.h` rồi điền `WIFI_SSID`/`WIFI_PASSWORD` (file này đã gitignore).

> **Vì sao dùng UART0?** ESP8266 chỉ có một UART phần cứng đầy đủ. UART1 (`Serial1`) **chỉ truyền**, không có RX (core đặt `rx_enabled = false` và ép TX ra GPIO2), nên không thể làm bridge hai chiều. `Serial.swap()` chuyển UART0 sang GPIO13 (RX) / GPIO15 (TX). Sau khi swap, USB không còn nối với UART0 — log debug đi qua TCP.

## 2. Sơ đồ đấu dây

| NodeMCU V3 | Nối tới |
|---|---|
| VIN (5 V) | Bus 5 V (khuyến nghị) |
| 3V3 | Chỉ dùng khi ngắt USB; không cấp đồng thời VIN và 3V3 |
| GND | GND chung với STM32 và nguồn |
| GPIO13 (D7, UART0 RX sau swap) | PA2 (USART2_TX của STM32) |
| GPIO15 (D8, UART0 TX sau swap) | PA3 (USART2_RX của STM32) |

Lưu ý:

- Không nối 5 V vào GPIO13/GPIO15; logic ESP8266 là 3,3 V.
- Nối chéo TX↔RX, nối chung GND.
- Không lấy nguồn ESP từ chân 3V3 của Blue Pill.
- Đặt tụ 470 µF/10 V + 100 nF sát chân nguồn module để chịu đỉnh dòng WiFi.
- **ESP-01S không tương thích với sketch hiện tại** vì không có GPIO13/GPIO15. Nếu dùng ESP-01S, phải bỏ `Serial.swap()` để dùng UART0 trên GPIO1/GPIO3 và nạp qua USB-TTL 3,3 V.

## 3. Nạp firmware

### 3.1 PlatformIO (khuyến nghị)

```bash
cd esp8266
pio run
pio run -t upload
```

> Sau `Serial.swap()`, `pio device monitor` (USB) **không còn log** vì UART0 đã chuyển sang GPIO13/GPIO15.

Hoặc từ thư mục gốc repo:

```bash
pio run -d esp8266 -t upload
```

Trình nạp trên NodeMCU V3 là USB-UART CH340G; chọn đúng cổng nếu có nhiều board.

### 3.2 Kiểm tra sau khi nạp

Sau khi swap, console USB **không còn log** (UART0 đã chuyển sang GPIO13/GPIO15). Log được đệm trong RAM và gửi qua TCP ngay khi client kết nối:

```
========================================
  ESP8266 BRIDGE – ROBOT MECANUM
========================================
[UART] UART0 @ 115200 (RX=GPIO13, TX=GPIO15)
[WiFi] SSID: iPhoneM
[WiFi] IP cua ESP8266: 172.20.10.10
[TCP] Server port: 8080
[READY] Cho ket noi TCP...
========================================
```

Kết nối TCP tới IP của ESP trên cùng hotspot.

## 4. Kết nối từ host

Laptop và ESP cùng kết nối một hotspot (SSID/mật khẩu trong `esp8266/src/secrets.h`). ESP nhận IP qua DHCP; xem IP trong log TCP (gửi khi client kết nối) hoặc danh sách client của hotspot.

```bash
cd host
source .venv/bin/activate
python3 main.py --tcp <IP_ESP>:8080
```

IP ESP do DHCP cấp nên có thể đổi sau mỗi lần khởi động lại. Cách chắc chắn nhất là để host tự dò qua UDP broadcast (ESP lắng nghe cổng 8266 và trả lời `ROBOT!<ip>:<port>`), hoặc dùng mDNS `robot.local`:

```bash
python3 main.py --discover
python3 main.py --tcp robot.local:8080   # nếu hệ điều hành phân giải mDNS
```

Mặc định `--tcp` không kèm địa chỉ dùng `172.20.10.10:8080` (IP hotspot iPhone trong quá trình phát triển):

```bash
python3 main.py --tcp
```

Chạy không cần GUI:

```bash
python3 main.py --tcp <IP_ESP>:8080 --monitor
```

## 5. Kiểm tra nhanh

Dùng `nc` hoặc `telnet` để xem telemetry:

```bash
nc <IP_ESP> 8080
```

Nếu thấy các dòng `T,...` khoảng 50 lần/giây là cầu nối hoạt động. Gõ `PING` phải nhận `PONG`.

Có thể dùng chế độ monitor của host để kiểm tra:

```bash
python3 main.py --tcp <IP_ESP>:8080 --monitor
```

## 6. Xử lý sự cố

| Hiện tượng | Kiểm tra |
|---|---|
| ESP không vào được hotspot | Kiểm tra `secrets.h`, sóng 2,4 GHz (ESP8266 không hỗ trợ 5 GHz), nguồn đủ dòng |
| Kết nối TCP được nhưng không có telemetry | TX/RX có bị đảo? Đúng 115200? STM32 đã cấp nguồn? |
| Telemetry bị ngắt quãng | WiFi yếu, giảm khoảng cách, tránh nguồn ESP sụt áp |
| Robot tự dừng sau 500 ms | Host không gửi lệnh 50 Hz hoặc TCP bị mất gói kéo dài |
| Nạp firmware thất bại | Cài driver CH340, chọn đúng cổng, giữ nút FLASH khi cần |
| Không kết nối được TCP | Chỉ một client được phục vụ; đóng kết nối cũ trước |

## 7. Giới hạn

- WiFi thêm trễ và jitter so với USB-UART; nên dùng USB-UART khi hiệu chuẩn PID.
- Timeout 500 ms trong firmware vẫn là lớp bảo vệ cuối cùng khi mất WiFi.
- Firmware bridge hiện chỉ phục vụ một client TCP tại một thời điểm.
- Bridge không kiểm tra/CRC dữ liệu, không xử lý giao thức; mọi lỗi định dạng do host và STM32 xử lý.
